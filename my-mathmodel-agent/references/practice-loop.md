# 数模练习与改进闭环

用于用户要求训练、限时演练或复盘时。训练对象是可复用的工作流程、工具与评测，
不是模型参数。不要把一次聊天里的纠正当成已经跨会话保存的能力。

## 一次练习

1. 读取原题与已有证据，选一个主要薄弱环节：题意拆解、选模、数据处理、验证、
   结果解释或论文表达。用户没指定时，依据已观察到的错误选择；没有记录时从题意
   和基线选模开始，不虚构弱点。
2. 开始前写清范围、时间预算、输入、产物及评分标准。默认采用约 30 分钟的小练习，
   用户指定的预算优先；记录实际耗时，不把估计当计时。不要自动扩展成完整论文。
3. 完成最小可验证产物：决策卡、可运行实验、复现记录或一个有证据的论文段落。
   数据不足时标明缺口；模拟数据只能证明实现可运行，不能证明现实结论成立。
4. 按预先标准评分，引用文件或运行证据，区分用户评分与助手自评。能独立复核时
   独立复核；同一上下文自评必须明确标注，不能声称独立审查。
5. 复盘每个主要失败：触发条件 → 观察到的错误 → 原因假说 → 最小修正 → 验证方法。
   有真实证据才补规则或脚本；不要为每次偶然错误添加一条永久禁令。
6. 换一题或新数据复测，并在可行时重跑旧案例检查回归。新题不提供原解或评分答案。
   没有换题复测前，结论只能是“规则已更新，效果待验证”。

## 评分

每项 0–5 分：题意忠实度、模型理由、验证质量、证据可追溯性、解释清晰度。
沿用 evaluation-rubric.md 的分数定义，记录每项证据，不只给总分。
局部练习中未涉及的维度标为不适用；论文完整性不应扣在选模练习上。
另记实际耗时、未完成项、用户介入次数和主要错误，不为速度牺牲正确性。
编造数据、核心结论无证据或题意改变时，该练习不能判为通过。

## 保存与接续

在当前比赛项目的 `planning/practice_log.jsonl` 追加每次实际练习记录，字段为：
`exercise_id`, `problem_path`, `focus`, `budget_minutes`, `elapsed_minutes`,
`criteria`, `artifact_paths`, `scores`, `reviewer_type`, `user_feedback`,
`failures`, `change_paths`, `transfer_check`, `next_action`。
未知值用 null；尚未复测写 pending。追加的是不同练习的历史，不是同一文档的 v2。
修改练习产物和 skill 时覆盖原路径；无实际练习时不制造空记录或虚构分数。

反馈保存到比赛项目文件，不擅自写全局记忆。新聊天从原 skill、项目进度与练习日志
恢复。只在执行数模任务时加载这些规则，避免影响其他任务。

## 何时改什么

- 对多题都适用的判断错误：修改原 skill 中对应规则，并给适用边界。
- 重复机械错误：优先修改或添加必要的检查脚本，实际运行验证。
- 某题的数据、假设、参数：留在该项目，不推广到整个 skill。
- 用户个人偏好：依用户授权保存在项目约定中，不把偏好包装成数学结论。

可直接使用的练习请求：
“用这道题做 30 分钟选模训练。先定评分标准，比较基线与主模型，运行一个最小验证，
最后记录失败原因。不要写完整论文；更新流程后另选一题复测。”
