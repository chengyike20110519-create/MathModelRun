# AI workflow 图的正确性门禁

用于 AI 生成的论文 workflow、模型机制图、状态图和概念示意图。
本模块补充 `figure-catalog.md` 与现有 Default-FAIL 合同，不替代数学验证。
用户喜欢 AI 生成的视觉风格时，保留这一偏好；美观和 O 奖质量是目标，不是获奖保证。
AI 图仅解释已经实现的模型逻辑，不能生成定量图表、实验观测或数据证据。

## 1. 先建立真实模型的图规范

生成前读取相关模型代码、验证记录、方法说明及 `paper/workflow.json`。
只读取这张图所需的链路；不能从参考论文或装饰图标补出不存在的技术。
把规范写入 `figures/<figure_id>.workflow-spec.json`，同时登记到 visualization plan。
每个实体使用稳定 ID，不能只凭颜色或空间位置识别。

| 字段 | 必须记录 | 对照证据 |
|---|---|---|
| `purpose` | 这张图解释的问题、可支持的结论和边界 | 对应论文小节与模型任务 |
| `nodes` | ID、类型、冻结显示文本、阶段序号、输入、输出 | 代码函数/公式/方法记录的位置 |
| `edges` | ID、起点、终点、关系类型、方向、冻结标签 | 数据传递、状态转移或反馈的实现 |
| `inputs` | 数据字段、来源、真实/假设/模拟属性、单位 | 输入文件与清洗/运行记录 |
| `outputs` | 输出对象、用途、产生节点 | 保存的模型输出或方法接口 |
| `variables` | 符号、含义、单位、允许范围、首次出现节点 | 符号表与代码/公式 |
| `labels` | 每块文字的精确字符串，包括标题、单位、图例 | 与论文术语、公式记号一致 |
| `layout` | 阅读方向、分支、并行关系、反馈路径、图例 | 拓扑规范，而非参考图的箭头数量 |
| `evidence` | 关联文件及 hash、实现/验证位置、模型版本 | 可重复查阅的实际产物 |

`edges.type` 至少区分 `dataflow`、`state-transition`、`control`、`feedback`。
计算依赖的箭头不能被图解或 caption 改写成已经证明的因果关系。
并行分支不能画成必须依次执行；时间步迭代不能画成整个流程任意回退。
状态图须检查守恒/流失/终止路径；反馈边须记录触发条件、时序和更新对象。
未实现的模型、未运行的算法、未经验证的数值、未知来源的地图都不得进入最终图。
装饰植物/动物图标可以示意研究对象，但不能伪装成实拍观测、测量或真实地点。

## 2. 冻结文本，再交给图像生成

先在纯文本中核对节点、边、变量、阶段顺序和反馈；将正确规范设为 `spec_status: frozen`。
冻结是内容核对，不等于生成图已通过；审查状态仍为 `pending`。
为规范计算 SHA-256；模型指纹包含相关代码、workflow 与已使用结果文件的 hash。
任何内容修改都重新冻结、重新计算指纹，不能沿用旧图的 PASS。
不得为了标题短、美观或复杂而改动已确认的算法名称、变量定义或关系。
允许有记录的换行、空格和排版，其他文本差异必须回到规范中明确批准。

生成提示至少包括以下内容，直接附上冻结的 nodes、edges 和 labels：

```text
这是论文概念 workflow，所有文字和关系以附带冻结规范为唯一内容来源。
逐字使用 labels；完整画出且只画出列出的节点、带方向连线与指定反馈。
保留 stage_order 和并行分支；每条连线有清楚的起点/终点，反馈不穿过标签。
使用统一图标与配色，文字在最终论文宽度下可读，给箭头和标签留出空间。
不增加模型、算法、实验值、照片证据、坐标轴或装饰性数据曲线。
输出清晰高分辨率图；若信息过密，按规范分成连贯分区，不能删改关系。
```

记录生成工具、提示文本、参考图、输出文件、尺寸、轮次和适用的 AI 使用说明。
生成结果可以作为标明“待审”的预览给用户看；`pending` 图不准插入论文。

## 3. 图后逐项核验，不能只评价好看

以冻结规范为标准，枚举最终图实际可见的文字、节点和连线，不能按预期补读。
先看全图，再放大各区，最后按真实论文宽度缩小；如需页内展示还要看实际 PDF 页面。
逐字比对全部 labels：拼写、数字、上下标、符号、单位、缩写和公式都要检查。
OCR 只作辅助；识别不出的文字记为未验证，不能由审稿者猜测后放行。
逐箭头检查端点、箭头头部、方向、标签、是否遗漏/多出，以及跨线是否引入歧义。
核对每个阶段的读序、并行分支、反馈触发条件和终止位置。
检查图与实现、`paper/workflow.json`、caption 的含义是否一致。
检查最终缩小后的字体、图标、颜色/灰度对比、清晰度、遮挡和裁切。
独立审阅者应读取冻结规范和确切图文件，不能修改被审图后继续沿用自己的审查结论。
环境支持时使用独立上下文/agent；不能取得独立审阅时保持 `pending` 并报告限制。

审阅者使用以下提示，不先阅读生成者的“已正确”评价：

```text
你是独立 workflow 图审阅者。以冻结规范、真实模型证据及确切图片为标准。
先抄录图中实际 labels 和 nodes，再逐条枚举箭头及方向；不要猜测模糊内容。
对照每个 ID：文字、端点、顺序、并行/反馈、变量单位、证据与图例是否一致。
查找凭空增加的算法、数值、伪观测和因果关系，以及最终尺寸下不可读的部分。
每项返回 PASS/FAIL/UNVERIFIED，指出图上位置、expected、observed 与证据。
只要有 FAIL 或 UNVERIFIED，整体不能 PASS；审查通过不代表模型本身有效或能获奖。
```

## 4. 审查产物和放行条件

使用 [../templates/figure-review.json](../templates/figure-review.json) 的共同格式，
写入 `figures/<figure_id>.review.json`，令 `kind=workflow`。原模板的scientific
检查替换为 `labels_exact`、`nodes_edges_exact`、`sequence_feedback`、
`claims_match_model`；每项都有 `status` 与具体 `evidence`。
可在检查项下增加 `details`，逐ID记录expected/observed、判定、图上位置及来源。
图中区域用像素bbox、裁图路径或明确区域描述，不能仅写一行“无问题”。

`files` 至少登记model、spec、caption、image、final_size_preview、grayscale_preview
角色，路径与真实文件对应；model角色可重复列出所有有关实现/验证/结果文件。
`builder` 是制图者身份，scientific和visual的reviewer须与其不同。
视觉检查沿用模板的三项，并对hierarchy/readability/comparison/finish各评0–5分，
本地交付目标每项≥4；这些是有具体观察依据的编辑判断，不是奖项预测。
无法辨识或未核验内容保留pending/fail，不允许用高美观分数抵消逻辑错误。

完成图、图注、规范和检查预览后运行
`python <skill>/scripts/figure_gate.py seal <review.json>`。
seal计算当前文件指纹，并将审阅重置pending；独立审阅员随后读取这些确切文件，
将逐项结果与当前fingerprint写入两类reviews，再运行 `check`。
脚本只验证文件新鲜度、审阅记录与未解决问题，不能自动识别错箭头或评价美观。

整体 `PASS` 需要文字、拓扑、顺序/反馈、模型一致性、证据属性、缩小可读性全部通过。
`checks` 或 VISUAL 证据为空、缺少独立审查、hash 未匹配时一律 `pending`。
错误、额外节点/边、模糊未验证文字、伪观测或未经验证数值一律 `FAIL` 并返修。
只有新鲜 `check` pass 才允许独立图交付或插入论文；据此更新visualization plan的passes。
图片重绘、文字/箭头叠加、裁切、换文件、模型变更或规范变更均使 review 失效并重审。
仅改变论文显示尺寸也须重新完成该尺寸的可读性检查；旧尺寸检查不能替代它。
插图后将scope改为paper，补paper_source、paper_pdf与rendered_page角色，重新seal
并审阅该页面中的确切图、内容与缩小效果。只有paper范围pass才算论文最终使用通过。

## 5. 有界返修，继续保留 AI 风格偏好

每轮输出 defect 清单和精确返修要求，针对错误重新生成，再完整审查确切新文件。
连续两轮失败时，优先减少单图文字、拆分合理分区或主图/辅图，按同一规范重新生成 AI 图。
不得以缩小字体、删掉关键边、改模型或放宽审查标准来使图片表面通过。
必要时保留 AI 图标/底图，添加可编辑的矢量文字和箭头层保证准确，并如实记录混合方法。
混合图也必须核对最终合成文件的所有 labels、edges 与 hash，不能只审文字层。
不要默认放弃用户的 AI 生成偏好；同时不要把未修好的图说成最终版或插入论文。
